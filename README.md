# Fake Review Detection Project

Welcome to the comprehensive documentation for our Fake Review Detection project. This project is designed to distinguish between computer-generated (fake) reviews and original (human-written) reviews by leveraging a variety of natural language processing (NLP) techniques, traditional machine learning models, and deep learning methods. In this document, we detail the project background, data processing, feature engineering, model experimentation, experiment tracking using MLflow, and finally, the deployment of our application.

---

## Project Overview

Fake reviews are a growing problem in the online ecosystem, impacting consumer trust and business reputations. Our project aims to automatically detect and flag these computer-generated reviews by analyzing textual content. To achieve this, we have employed various techniques including:

- **Text Preprocessing:** Cleaning and normalizing text data.
- **Feature Engineering:** Extracting useful metrics such as lexical diversity, sentiment scores, and syntactic patterns.
- **Embeddings:** Generating different embeddings using methods such as TF-IDF, Count Vectorization, and precomputed embeddings from models like BERT and GloVe.
- **Model Training:** Experimenting with a range of traditional machine learning models (Logistic Regression, Random Forest, SVC) and a more complex deep learning model using a two-layer LSTM.
- **Experiment Tracking:** Logging every experiment with detailed metrics, hyperparameters, and artifacts using MLflow.

---

## Data Collection & Preprocessing

Our data consists of review texts along with corresponding labels indicating whether a review is computer-generated or original. The preprocessing pipeline includes:

- **Text Cleaning:** Removing unwanted characters, punctuation, and noise.
- **Normalization:** Converting text to lower case, tokenizing sentences and words, and applying techniques such as stemming, lemmatization, and stop word removal.
- **Feature Extraction:** Calculating metrics like lexical diversity, average word length, sentiment polarity, subjectivity, Flesch Reading Ease, sentence length, and various part-of-speech counts.

Processed data files are stored in our `../Data/Feature-Engineered/` folder.

---

## Feature Engineering & Embeddings

To capture the nuances of textual data, we explored several embedding techniques:

- **TF-IDF Embeddings:** Transforming text into weighted term-frequency representations.
- **Count Vectorization:** Creating basic term-frequency vectors.
- **Precomputed Embeddings:** Using models such as BERT and GloVe to generate embeddings, which are stored as CSV files in the `../../embeddings/` folder.

These methods provide diverse representations of the data, enabling our models to learn both syntactic and semantic patterns.

The datasets used by the scripts in `src/` are included in this repository: `Data/Raw/fakeReviewData.csv` (Amazon reviews) and `Data/External/` (MAGE extracts written by `src/prepare_mage.py`). The intermediate files produced by the exploratory notebooks (`Data/Pre-processed/`, `Data/Feature-Engineered/`) can be regenerated by running notebooks N0–N2.

## Modeling Approaches

### Traditional Machine Learning Models

We experimented with several scikit-learn models:

- **Logistic Regression**
- **Random Forest Classifier**
- **Support Vector Classifier (SVC)**

For each model, we performed hyperparameter tuning using GridSearchCV with feasible parameter grids. Experiment results, including confusion matrices and metrics (accuracy, precision, recall, F1 score), are logged in MLflow.

### Deep Learning Models

To capture complex patterns, we built a deep learning model using TensorFlow Keras:

- **Two-Layer LSTM:** The model includes an embedding layer, two LSTM layers, and dense layers with dropout for regularization.
- **Text Tokenization & Padding:** We convert raw text into sequences using Keras’ Tokenizer and pad them to a uniform length.
- **Evaluation:** Model performance is evaluated on standard metrics and confusion matrices are logged.

## Experiment Tracking with MLflow

Our experiments are fully tracked using MLflow. For every run, we log:

- **Parameters:** File names, model types, hyperparameters, and embedding types.
- **Metrics:** Accuracy, precision, recall, and F1 score.
- **Artifacts:** Confusion matrices (as PNG images) and model artifacts.
- **Datasets:** Using the `mlflow.data` API, our dataset information is logged and appears under the MLflow UI's "Datasets" tab (for MLflow ≥ 2.4). When unavailable, the CSV files are logged as artifacts.

## Production Pipeline

The web app combines two models: a scikit-learn pipeline (below) and a deep learning BiLSTM (see [Deep Learning Model and Ensemble](#deep-learning-model-and-ensemble)). The pipeline is trained by `src/train.py` as a single object, so the app computes features exactly the way the model was trained on them. Feature code lives in `src/features.py`.

**Signals used by the model:**
- **Word patterns:** TF-IDF over word unigrams and bigrams (top 50,000).
- **Sentiment:** TextBlob polarity and subjectivity, plus the mismatch between sentiment and the star rating.
- **Repetition:** repeated phrases within a review and lexical diversity.
- **Text similarity:** cosine similarity to the closest training review and the number of near-duplicate training reviews.
- **Style:** word and sentence length, readability, punctuation, uppercase and exclamation usage.

**Data and splits.** Reviews are deduplicated by text (lower-cased, punctuation and spacing collapsed) before splitting: 40,401 of 40,432 remain. Split: 80/20 train/test, then 85/15 fit/validation, stratified, seed 42 (27,472 / 4,848 / 8,081 reviews).

**Results on the held-out test set** (8,081 reviews; regularization strength and feature groups chosen on the validation split; test accuracy is shown for every configuration but never used for selection):

| Features | Validation accuracy | Test accuracy |
|----------|---------------------|---------------|
| TF-IDF only | 94.20% | 94.72% |
| TF-IDF + stats | 94.72% | 94.94% |
| TF-IDF + similarity | 94.39% | 94.60% |
| **All features** (selected; refit on fit + validation) | **94.97%** | **95.26%** (precision 95.01%, recall 95.55%, F1 95.28%) |
| Stats + similarity only (no words) | 87.23% | 85.63% |

Full metrics are written to `Reports/metrics.json` and `Reports/confusion_matrix_pipeline.png`; confidence intervals and paired tests to `Reports/analysis.json` (`python analysis.py`). The figures in an earlier version of this README (96.57% ensemble accuracy etc.) came from the models now kept in `original_artifacts/`; the audit reproduced them exactly from those files (see `EXPERIMENT_VERIFICATION.md` one folder up).

### Deep Learning Model and Ensemble

`src/train_dl.py` trains a **bidirectional LSTM** on the same train/validation/test split. It reads the raw review text: a built-in tokenizer (20,000-word vocabulary, first 200 words of each review) feeds a 64-dimensional embedding, a BiLSTM layer with 64 units per direction, and a dense layer. Training stops early when validation accuracy stops improving (4 epochs; best epoch kept). The app averages the probabilities of the two models (both are P(Original)).

| Model | Test accuracy [95% CI] | Precision | Recall | F1 |
|-------|------------------------|-----------|--------|----|
| Logistic regression pipeline | 95.26% [94.78, 95.73] | 95.01% | 95.55% | 95.28% |
| BiLSTM (deep learning) | 94.70% [94.21, 95.20] | 93.90% | 95.62% | 94.75% |
| **Ensemble (deployed)** | **96.24% [95.83, 96.67]** | **95.83%** | **96.69%** | **96.26%** |

The ensemble is significantly better than either model on the same reviews (exact McNemar p < 1e-5); the two single models do not differ significantly (p = 0.05).

**Caveat:** 65% of the computer-generated reviews in this dataset end mid-sentence (vs 9% of genuine ones). Removing unfinished final sentences from the test reviews lowers ensemble accuracy to 92.2%, so part of this accuracy comes from that artifact of how the dataset was generated.

The training curve is saved to `Reports/dl_training_curve.png`.

### Decision Threshold

Each prediction is a probability that the review is Original; reviews below the threshold are labelled computer-generated. `src/choose_threshold.py` picks the threshold automatically: the highest value that flags **at most 1% of genuine validation reviews**, then checks it once on the test set. It is saved in `src/model_config.json` together with SHA-256 fingerprints of the models it was calibrated for; if the models change, the app and `predict.py` warn that the threshold is stale instead of using it silently. It can still be changed with the slider or `--threshold`.

| Threshold | Genuine reviews flagged | Computer-generated caught | Accuracy (test set) |
|-----------|-------------------------|---------------------------|---------------------|
| **0.26 (default, automatic)** | **1.11%** [0.83, 1.49] (validation: 0.99%) | **89.82%** | **94.36%** |
| 0.50 | 3.31% | 95.79% | 96.24% |

The 1% target holds on the validation reviews it was chosen on; on new reviews the rate varies (here 1.11%).

### Modern-AI Check (ChatGPT, GPT-4, LLaMA)

The computer-generated reviews in the Amazon dataset come from GPT-2-era generators and show their typical flaws: sentences cut off mid-way, sentences run together, repetition and incoherence. The models above learned to detect those flaws, and caught **0%** of reviews written by modern models such as ChatGPT and GPT-4, which are fluent and coherent.

We first tried retraining with modern AI reviews from the [MAGE benchmark](https://huggingface.co/datasets/yaful/MAGE) (Li et al., 2024: Yelp reviews from humans and 27 language models). It lowered Amazon accuracy (96.6% to 95.1%) while catching only about 20% of ChatGPT reviews and none of the unseen GPT-4 ones: TF-IDF features and a small LSTM are not strong enough for fluent modern text. That training option is kept in `src/train.py` (`USE_MAGE`) but switched off.

Instead, the app adds a **second check**: the pretrained transformer detector released with MAGE ([`nealcly/detection-longformer`](https://huggingface.co/nealcly/detection-longformer), `src/modern_detector.py`). A review is labelled computer-generated if **either** check flags it. The detector is pinned to revision `61d3aab` and run with MAGE's own recommended text preprocessing (`src/mage_preprocess.py`, up to 4,096 tokens); the original setting (raw text, 512 tokens) is still available as `--mode project` and was less accurate on validation data. Its threshold (0.9982 probability of AI) is chosen by `src/calibrate_modern.py` to flag at most 1% of 450 validation human reviews and stored in `src/model_config.json`. Results on test reviews, with 95% intervals:

| Test reviews | Main models only | **With the modern-AI check** |
|--------------|------------------|------------------------------|
| Genuine Amazon reviews wrongly flagged (300) | 1.3% | 2.3% [1.1, 4.7] |
| Genuine Yelp reviews wrongly flagged (150) | 0.0% | 0.0% [0.0, 2.5] |
| Genuine IMDb reviews wrongly flagged (200) | 0.0% | 1.5% [0.5, 4.3] |
| Amazon GPT-2-era fakes caught (150) | 86.7% | 89.3% [83.4, 93.3] |
| ChatGPT reviews caught (Yelp, 99) | 0.0% | **69.7%** [60.0, 77.9] |
| Other modern AI reviews caught (Yelp, 100) | 0.0% | 62.0% [52.2, 70.9] |
| **GPT-4 reviews caught (IMDb, never used in training, 200)** | 0.0% | **92.5%** [88.0, 95.4] |

Limitations:
- The combined system flags about 2% of genuine Amazon reviews, above the 1% target (all four validation false alarms were Amazon reviews; IMDb has no validation data).
- **The modern-AI threshold is unstable.** It is a 1% tail cut-off estimated from 450 reviews: re-drawing those reviews (bootstrap) moves ChatGPT detection anywhere between 11% and 83%. An earlier version of this project reported 78.8% ChatGPT / 96.5% GPT-4 with the same detector scores but a different validation sample. Calibrate on a much larger set of human reviews before relying on these rates.
- It works best on longer reviews (modern AI caught: 89% of reviews over 80 words, 56% at 41–80 words, 0 of 12 at 21–40 words).
- It is slow on a CPU (about 1.3–1.7 seconds per review) and needs the optional packages in `requirements-modern.txt`.
- The Yelp figures are optimistic because the detector was developed on MAGE data; the GPT-4 figures are a fairer out-of-distribution test.

**Explainability:** for every prediction the app shows a table with both checks' scores, thresholds and decisions, and which check triggered the flag. The logistic regression is linear, so its logit is shown as intercept plus per-word and per-signal contributions; these explain only that model (not the BiLSTM or the modern-AI check). It also lists the most similar training reviews with their labels; similarity is evidence of shared wording, not proof of authorship.

**Retrain** (Python 3.10–3.12; TensorFlow does not import on Python 3.9.0):
```bash
cd src
python train.py      # about 6 minutes; writes src/model_pipeline.joblib and src/similarity_index.joblib
python train_dl.py   # about 6 minutes on CPU; writes src/dl_model.keras, ensemble metrics, Reports/test_predictions.csv
python choose_threshold.py   # about 2 minutes; Stage A threshold -> src/model_config.json
python prepare_mage.py       # downloads MAGE (~550 MB) and writes Data/External/ (already included)
python calibrate_modern.py --mode project   # Stage B scores, original setting (raw text, 512 tokens)
python calibrate_modern.py --mode mage      # Stage B scores, MAGE's reference preprocessing (needs clean-text)
python calibrate_modern.py --mode <chosen> --reuse --deploy   # make that setting's threshold the default
python analysis.py --modern project mage    # CIs, paired tests, robustness and calibration analyses
```

**Tests** (`pip install -r requirements-dev.txt`, from the repository root):
```bash
python -m pytest -q tests
```
Tests that need the dataset, the saved models, PyTorch or clean-text are skipped when those are missing.

## Running the App

The Streamlit web app takes a review and its star rating, predicts whether the review is computer-generated or original, and explains which words and signals drove the prediction.

Use Python 3.10–3.12 (TensorFlow does not import on Python 3.9.0):
```bash
python -m venv .venv
source .venv/Scripts/activate   # Windows (Git Bash); on macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
pip install -r requirements-modern.txt   # optional: the modern-AI check (~1 GB)
streamlit run src/app.py        # opens at http://localhost:8501
```

**Whole datasets:** the app's **Batch (CSV file)** tab takes a CSV with one review per row. Choose the text column, and optionally a star-rating column and a true-label column (CG/OR or 0/1). It shows how many reviews were flagged, accuracy if labels are given, and lets you download every prediction as a CSV. From the command line:
```bash
cd src
python predict.py reviews.csv --text-column text_ --rating-column rating --label-column label -o predictions.csv
```
The main models run at roughly 100 reviews per second on a laptop CPU (the full 40,432-review dataset takes about 4 minutes). The modern-AI check takes about 1.5 seconds per review, so it is optional for large files (`--no-modern` on the command line). Scoring the project's own dataset gives higher accuracy than the held-out figures, because most of it was used for training.
